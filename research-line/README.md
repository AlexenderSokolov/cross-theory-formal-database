# research-line —— 研究级逐条精读产物（**非交付语料**）

## 这是什么

这是本项目"研究级材料线"的产物：**逐条深读原始文献**产出的**完整题证单元**。

每一条单元包含四件东西：

1. **完整题面**（作者原文，逐字）；
2. **作者完整证明**（作者原文，逐字）；
3. **针对本题的 `difficulty_reason`**（不是模板：写清实质要求／允许引用什么／哪些部分必须由本证明完成／原文定位）；
4. **statement / proof 定位**（源文件名 + 行号区间）。

## ⚠️ 它没有经过什么（请务必先读这一节）

- **它没有经过交付门禁 `verify_item.py`**，也不是交付包格式（无 `package-root` / 回执 / 编译产物）
  ⇒ **它不是 `editable-corpus/` 那种"已交付语料"**，**不要按已交付语料去消费它**。
- **它没有走过准入 → 冻结 → 合并 → 发布**那条链。
- 每条 `items/*.tex` 是**可编辑的 LaTeX 片段**（题面 + 证明连在一起），**没有独立编译过**
  （它们是材料，不是成品题包）。
- **难度档位是本线自己判的**，不是权威结论：判据为
  (i) 决定性的一步由本证明承担；(ii) 结果本身研究级；(iii) **不是常规辅助步骤**（见下"口径修正史"）。

## 文件结构

```
research-line/
├── README.md            ← 本文件
├── index.jsonl          ← 权威索引（派生文件，从 reasons*.json 的 items[].difficulty_level 重建）
├── items/<problem_id>.tex   ← 每条单元（头部注释含 source_file / locator / env / status）
├── reasons.json         ← B1 的难度理由与判定记录
├── reasons2.json        ← B2
├── … 至 reasons12.json  ← B11
├── batches/             ← 早期批次的题目副本（B1–B4 + R1）
└── raw/                 ← PDF 来源的原页渲染图（用于逐字核对，如 lurie-p36.png）
```

## 质量机制（哪些是真的硬）

- **逐字性靠脚本**：抽取器做**紧配对**校验（命题后紧跟的第一个环境必须是 `proof`，否则丢弃）；
  全量审计：Stacks 8,919 条 **0 处**不匹配、HoTT 252 条 **0 处**不匹配。
- **判定不自证**：每条 H3 至少**两名独立复核员**，做法固定为
  ① 自己读源做**机器 diff**（文字偏差与行号偏差分开报告）；
  ② **逐 ref 核实**"没有任何被引件以本条结论为前提"；
  ③ **诚实记录反向证据**（若存在更低档读法，写出来并说明为何不采纳）。
- **索引派生**：`index.jsonl` 每次从权威字段重建，**结构上不可能累积重复**。

## 已知缺陷（如实列出）

1. **引文曾有 12 处不忠实**（全部由复核员机器 diff 抓出并已修正）：3 处静默改写了原文笔误、
   8 处跨行并句／去 LaTeX 定界符／截断未标省略号、**1 处编造了一句原文不存在的引文**（拼接两行并替换符号）。
   根因：**脚本提取的部分从不出错，手写引文时会漂**。
2. **轮换不深**：211/235 来自 Stacks 一个来源块。
3. **档位判定史有一次系统性偏宽**（见上"四项指标"），相关条目均保留了 `level_before_recheck` 与
   `recheck` 字段，**可审计、可回溯**。

## 给接手者的最短路径

- 想**看某条题目与证明**：读 `items/<problem_id>.tex`（头部注释给出源文件与行号，可直接回原文核对）。
- 想**看难度理由与判定依据**：在 `reasons*.json` 里按 `problem_id` 查，含 `difficulty_reason`、
  `h3_criterion_note`、`two_criteria`，以及（若被复查过）`level_before_recheck` 与 `recheck`。
- 想**统计**：只用 `index.jsonl`（派生自权威字段）。
