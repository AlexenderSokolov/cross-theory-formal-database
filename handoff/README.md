# 高级数学人类证明题库本地交接

这份交接把已有题源、完整题证、待处理工作和执行经验交给本地接续。新的目标是 **30,000 道合格唯一题**；本次完成的是交接，不是三万题采集。

## 当前材料

- 主库：975道完整可编辑题证，已提交并核验，含全文SQLite恢复分段
- 待合并：40道完整规范题证与全文SQLite；其中27道已组成可恢复的本地1002题整包，另13道独立封存，不能重复相加
- 待完成：1907仅有部分合规材料，不计入完成数
- 题源目录：3,255条材料记录；扩展题源：44个核查入口
- 三万题：本地后续目标，本次没有声称已完成

精确提交与各口径见 [状态快照](STATUS_SNAPSHOT.json)。

仓库克隆后可先执行 `cd handoff && sha256sum -c SHA256SUMS` 核对这份交接的全部列明文件，再返回仓库根继续。

## 从这里开始

1. 阅读 [最终状态快照](STATUS_SNAPSHOT.json)，分清远端已交付、本地通过、来源准入和历史线索；不要把旧三千多条PDF证据当作完整可编辑题数
2. 按 [本地命令手册](plan/04_COMMANDS_AND_RECOVERY.zh-CN.md) 克隆、恢复全文SQLite并核对当前题库
3. 用 [给本地执行器的完整指令](plan/03_LOCAL_AGENT_PROMPT.zh-CN.md) 启动接续，连同 [硬性标准](plan/01_SCOPE_AND_STANDARDS.zh-CN.md) 和 [三万题执行计划](plan/02_EXECUTION_PLAN_30000.zh-CN.md) 一起交给本地模型
4. 先接收待合并规范包，再处理既有来源队列，随后轮换新增来源；不要重复下载、转录、计数或重编号

## 材料边界

已交付题目在仓库`editable-corpus/`，以其不可变manifest和数据库分段为准。`materials/`与`pending/`提供本次便携待合并／未完成材料的恢复清单和阅读入口；最终材料索引列明哪些文件真正随Git交付、哪些仅是历史路径/哈希和合法重新获取线索。

原始抓取HTML、隐藏请求字段、私有非独占源包、未核验再分发权限的内容不混入Git；最小许可事实见证和对应合法原件保留。1910已来源准入并规范化；1907明确仍未完成，不能计数。原临时路径是历史信息，不是要求本地存在同样目录。

仓库可见性须与用户实际授权的受众范围一致；本交接不改变可见性。不同来源的GFDL、CC BY、NC、SA等条件继续按条目保留，不用一个统一的宽松许可证覆盖全库。

## 接续的第一件事

固定交接提交、核对文件与数据库，再在本地做20道闭环并测量真实吞吐。按25—100道可恢复提交、每500道全库检查与常规汇报推进。规模计划建立在实测合格产率上，不通过拆引理、降难度或把文献量当题量达到三万。
