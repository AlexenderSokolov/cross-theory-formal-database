# 三万道高级数学人类证明题库规范

## 本次交接的目的

把已有材料、来源、处理经验和实际状态交给本地执行器，在同一套标准下扩充到 **30,000 道合格、唯一、可追溯的题目**。本次交付是接续工作包，不宣称已经完成三万题，也不再要求云端先完成旧的三千／五千目标。

已有文献链接和 PDF 证据是重要资产，但不是完整可编辑题证的完成数。历史计数、候选记录数、不同文献数、来源准入数、本地通过数、GitHub 已核验交付数必须分别报告。当前精确数值看交接根目录的状态快照与 catalog 的统计；最终条目数以对应提交中的实际 manifest 和 SQLite 为准，不能用文件夹数或历史状态字段替代。

## 一个合格条目是什么

1. 一项具有独立内容的证明任务。沿用作者原命题及其真实假设；可以是定理、命题、具有独立实质内容的引理，或已有完整人类解答的高级习题
2. 完整原题、必要背景、完整作者证明，以及本题应承担的全部新局部核心论证，都在可编辑正文里。跨页、附录、非相邻续证、必要图表／记号不能漏取
3. 作者、作品、实际版本、DOI／实际来源 URL、原命题与证明位置、原文件哈希、获取记录和许可证可追溯
4. 数学难度明确高于普通博士资格考试，只有 H1、H2、H3 三档及 2—4 句具体依据
5. 独立 TeX 可以实际编译；题证正文不能只是 PDF 包装、图片、链接、摘要或“稍后补充”。必要几何示意图可作为有明确许可的资产；图中的关键数学文字／公式须可编辑或按当前严格转录标准处理
6. 按语义去重后入 INDEX，与清单、来源记录和全文 SQLite 一致，实际通过当前门禁，并在交付位置核验

同一问题的多份解答、重印、改名、语言版本、参数换写、TeX／Lean 两种表示，只计一道。不要用相邻辅助引理、证明中的小步骤或简单特例增加数量。实质不同的结果可以来自同一篇论文，但必须分别说明独立的结论和证明义务。

## 难度与标注

| 等级 | 含义 | 必须给出的依据 |
|---|---|---|
| H1 | 明确超过通常博士资格考试 | 指出具体非例行构造、结构论证、精细估计或极限／存在性义务 |
| H2 | 博士高阶专题中仍有实质证明任务 | 明确背景之后，仍需本题完成哪段主要论证 |
| H3 | 已存在完整人类论证的研究级结果 | 界定核心范围，排除论文中的常规辅助步骤 |

允许引用原文中明确、可定位的标准先修结果；不递归重证所有基础。不能把本题的主结论、等价结论、新关键构造或主要常数推导假设为已知。难度不以期刊、作者、篇幅、术语数量、模型失败率或引用量代替。

初始建库**不做 a/c、跨理论、距离、工具、桥梁、学科类型等研究标注**，也不按未来希望观察的现象定向选题。来源指南按主题组织只是检索导航，不是给题目加研究标签。作者署名、版本、出处、许可证、状态属于材料管理，照常保留。旧标签和旧采样背景留在历史材料，不抹掉其来源偏向。

旧计划中的冲突按本规范解决：其开头和用户后续要求优先于遗留的 a/c 小节；用户后续明确要求的实际编译、GitHub 和全文 SQLite 保留；“不另建平台”继续落实为不先建网站或复杂调度系统。

## 人类证明与检查边界

默认保留作者语言、证明顺序、量词、符号、假设、常数及条件性。助手的题名、难度理由、排版说明、异常注记与作者正文分开。条件性结果必须在题面保留原假设；不能把“假设某猜想则……”写成无条件定理。

本轮检查实际取得的来源、题证对应、核心完整性、转录忠实、引用与排版、稳定编译、去重和交付一致性。**不启动独立数学审稿、多模型投票、自动反例研究或替代证明竞赛。** 不让模型补造缺失证明。普通作者排版／标号瑕疵保留并注明；若发现关键缺失、关键符号无法辨认、版本不匹配或题证不对应，转入待澄清，不通过猜测修复。门禁通过不等于独立证明该论文的数学正确性。

Lean 可以作为另一种表示，但须固定仓库提交、工具链、依赖和人类作者来源；不能用导入现成结论的包装 theorem、`sorry`／`admit`、新增假设或生成证明冒充完整人类题证。只按原独立问题计数。当前主交付门禁针对 TeX，Lean 全量接纳接口仍是本地后续任务，未实现前不得挤入 TeX 已通过计数。

## 来源许可与安全

目标为 `AlexenderSokolov/cross-theory-formal-database`。每次发布前核对实际可见性与已批准受众；不擅自修改可见性或访问权限。这里的发布清单规定可发送材料边界，不构成改变受众的授权。逐来源许可证、私有辅助材料边界和用户受众许可分别满足；私有转公开时须先取得明确公开授权。

- 开放阅读不等于允许再分发；逐组件区分作者原生 TeX、出版 PDF、图片、字体／宏包与整理说明的权利
- 原生源有明确兼容许可时优先复用。arXiv 的 nonexclusive 分发许可不能当作公开复用许可；这类源最多作为私有、未执行的辅助材料，公开内容应以有明确许可的出版版本作严格转录依据
- ND、NC、SA、GFDL 等条件必须单独记录并遵守；不把全库统一标成一种开放许可证。无法确认的作品保留元数据／链接为发现线索，不公开复制全文
- 每份许可证说明都从**当前**文章的作者、题名、DOI、确切版本与证据生成，禁止整段复制另一题的归属说明或不适用的修改说明
- GitHub 只放最小、可读的事实性许可见证与必要原件。抓取 HTML 中的表单、脚本、隐藏请求字段、会话值等不公开；原始响应保留私有。旧错误材料中的敏感字段也不能以“历史备份”为由上传
- 不运行下载论文中的类文件、Makefile 或未知脚本。使用已核对的数学正文、有限宏和可信已安装依赖；编译禁用 shell escape，编译账户／容器不要暴露 SSH、API 或登录凭据
- 403、登录障碍、验证码、封禁和明确拒绝不能靠换账号、镜像、缓存或其他工具绕过；记录并换合法来源。不存在的文件和临时网络失败与访问拒绝分开处理

## 状态与计数

建议在候选台账中使用以下清晰状态，不覆盖原状态：

`discovered → source_acquired → source_reviewed → tex_ready → locally_validated → published_verified`

另设 `hold_missing_proof`、`hold_difficulty`、`hold_rights`、`hold_access`、`hold_rendering`、`duplicate`、`rejected`、`in_progress`。状态是调度信息，不是研究标签。已交付后的勘误用新版本追加；不能把失败记录删掉，或把历史门禁状态悄悄改成当前通过。

fail-closed 作用于失败的题／批次与发布依赖：缺项不得进入合格数，但不阻塞完全独立、已经通过的其他题。只有共用运行程序、清单、许可证或来源身份出现问题时，才暂停受影响范围的交付。

## 许可范围的具体区分

作者公开文章自身的数学宏和排版前导，不因文件名含 author-preamble 就自动成为私有材料。须核对确切公开来源、版本、适用许可及逐字节提取关系；许可覆盖且属于必要输入的作者宏应随正文保留。未经许可的出版社类文件、第三方宏包实现、私有非独占辅助源码和凭据仍分别排除。不能仅凭同站托管、文件名或项目内部“已批准”记录推定全部文件都可再分发。
